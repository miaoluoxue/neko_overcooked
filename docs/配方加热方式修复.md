# 配方加热方式修复（2026-09-18）

## 证据

热气球关卡日志曾出现把 UncookedFish 放入 utensil_pot_01。食材知识允许鱼进入多种容器，但这不代表每种加工方式都符合订单。

反编译 `CookedCompositeAssembledNode.IsMatch`：IL_0019–002f 比较两棵料理树的 `m_cookingStep.m_uID`，IL_0034–0040 比较熟度。原桥的 RecipeReader 只输出熟度与食材，遗漏加工方式，Python 无法按订单区分。

## 改动

- RecipeReader 在 cook 节点增加 cookId，直接来自游戏对象，不硬编码鱼、虾或锅具名称。
- 普通食材的配方步骤保存 cook_id。同名食材的不同出现位置分别保留要求。
- 选空锅、查找已有食材、动作评分、取菜判定及烹饪台账复用均检查加工方式，已知不匹配时跳过。
- 旧桥没有字段时保留原行为。搅拌后烘烤的组合步骤暂未传播此字段；本次覆盖当前意面关卡的普通烹饪链。

## 验证

87 项回归测试通过。新增测试覆盖同种食材对应两种加工方式、跳过不匹配空锅与已有食材、无匹配锅和旧字段兼容。内存中恢复旧选锅行为后，新测试按预期失败。

使用 Microsoft.Net.Compilers.Toolset 4.8.0 编译。安装前备份为 build/Overcooked2AI.before-recipe-cook-id.dll；安装文件与构建文件 SHA-256 一致：37DE2A4780F094C9C8D18397532C05A02787465FC580F7F8A6853E873E692C5E。

部署前第 53 局送出 4 份、186 分，未达到 260 分。通关效果仍需实机验证。

实机复核：重启后已自动继续同一存档进入 s_balloon_2_3。配方返回 Pasta=20068（Pot），BurritoMeat/Prawn/UncookedFish=20294（FryingPan），推导后的 cook 步骤保持同一 ID。P1、P2 的 stale 和 engine_stale 均为 false。
