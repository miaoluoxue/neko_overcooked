## 三分钟版

**平时什么都不用设。** 需要改的只有三样，而且它们都该写进 `runtime/watch.local`：

| 你要干的事 | 配什么 |
|---|---|
| 两个脚本自己打 | `NEKO_WATCH_CHILD=run_team.py --input keys,virtual` |
| 一个键盘一个手柄 ⇒ **必须保持前台** | `NEKO_WATCH_KEEP_FOCUS=1` |
| 开递归规划器 | `NEKO_PLAN=on` |

配好之后：`python -u run_watch.py`。

## 参数本地化：`runtime/watch.local`

每开一次终端都要 `set` 一串环境变量，忘一个就跑成另一个配置 —— 而**跑错配置的代价是一整局**。
所以参数可以从一个本机文件读（`runtime/` 是 gitignore 的，不进仓库）：

```ini
# 每行 KEY=VALUE; # 开头是注释; 值里的 = 和空格都原样保留
NEKO_WATCH_CHILD=run_team.py --input keys,virtual
NEKO_PLAN=on
NEKO_WATCH_KEEP_FOCUS=1
```

- ☠ **显式设的环境变量优先于这个文件**（走 `setdefault`）——
  临时改一格 `set NEKO_PLAN=shadow` 仍然管用，不用去动文件。
- ☠ **这个文件能放下面这张表的全部 49 个，不只是看护那 11 个。**
  看护起子进程时 `Popen` **不带 `env=`** ⇒ 整个环境变量原样传给子脚本
  （实测：文件里的 `NEKO_PLAN` / `NEKO_STEP_COOLDOWN` 子进程都收得到）。
  ⇒ **一个文件配完所有东西**。
- 换路径：`NEKO_WATCH_LOCAL=<别的文件>`；**关掉它**：`NEKO_WATCH_LOCAL=0`。
- 它由 `run_watch.py` 读取（`parse_local_config`，纯函数，`runtime/_watch_probe.py` 有断言）。

## 递归规划器

| 变量 | 默认 | 干什么 |
|---|---|---|
| `NEKO_PLAN` | **`on`** | **默认开**（2026-09-17 起）／`shadow` = 算计划+打日志、**不改行为**／`0` = **一键回退**（与加它之前逐字相同） |
| `NEKO_PLAN_TTL` | `20.0` | 一份计划能用多久（秒）。过期就当没有 —— 这是"动态地图"那条的落地。☠ 判的是**计划自己的算出时刻**，不是"我读到的时刻" |
| `NEKO_PLAN_INTERVAL` | `6.0` | 多久重算一次（秒）。⚠ 某步**真失败**时会跳过节流立刻重算 |
| `NEKO_PLAN_BONUS` | `8.0` | "这一步是计划排给我的"奖励分。只加不减 |

`on` 走的是**软闸门 + 奖励分**（不是另写一个调度器）：
`_plan_next` 只放行计划排给我的那一步、`_plan_bonus` 给那一步 +8；
**这一步这一轮做不到就退回整池** —— 那正是"绝不停机"。

收窄的三条边界（2026-09-17 定）：
- **只收"计划覆盖的那几张单"的步** —— 归属按**槽位键**对（`_plan_flow` 返回一组槽位键，
  取自 `Plan.slots`），不靠菜名。同名多单里长得一样的步骤不会被一起收进来。
- **杂活留着** —— 计划管的是"菜谱那几步的顺序"，不是"别的活都别干"。
  （救锅另有硬上限兜底；但洗盘子/开火/到点取菜不该因为计划命中就停。）
- **可达性逐条判** —— 收窄前把此刻够不着的那几条**剔掉**，剩下的照常收窄；
  一条不剩才退回整池。老的"全部可达才收窄"在计划横跨几张单时会让整份计划
  被静默忽略（一张单那一步不可达 ⇒ 三张单的计划全不生效）。

★ **计划覆盖整个订单池**（`planner.plan(flows, …)`，2026-09-17）：`_plan_tick` 自己
建池（最多 `NEKO_COOP_ORDERS` 张单），所以 `NEKO_COOP_ORDERS` **同时**是
"候选池几张单"和"计划覆盖几张单"的上限。

形状是用户定的：**只覆盖到池，不在规划期排人** —— "谁做哪一步"仍旧交给
**执行层的评分 + 步级占位**去错开两个人。合并计划 = **无交并**：每张单各走一遍
它的链，拼起来、`deps` 整体偏移、每步盖上槽位键（`Step.slot`）；跨单**不建**依赖边。
某张单推不出解 ⇒ **跳过它**（打一行 notes），不把别的单的计划一起扔掉。

### 「这一步没有货源」不再拿满分（`NEKO_NOSRC_PENALTY`，2026-09-17）

用户原话：**"菜单的制作链有问题"**。实机 `s_balloon_5_2` 的订单卡：

```
1. fetch Bun  (⚠ 找不到货源(箱子/生料/成品都没匹配上))
```
引擎自己也认了：`⚠ BeefBurgerMax: **重拉知识表后还是找不到货源** —— 这关可能真的没有这种料`。

☠☠ **可这个信号全仓只有 `_derive_with_retry` 一处读它** —— 评分、候选池、`⊕备料`、
执行层**一处都不看** ⇒ 一个**已判定不可行**的步骤照样拿 `fetch` 的**满分 20** 并被反复选中：

```
17. fetch Bun ⊕备料   ✓ 0.0格  20分  → 选
[步骤] 拿到的是 'ChoppedBun', 不是 'Bun' → 放回去
```
整单从 **99% 烧到 63%**，一个料都没进去。

现在两处接上了这个信号：
- **菜谱步**：`nosrc` 的候选**扣 `NOSRC_PENALTY`**（默认 60 = `assemble` 的步骤价，
  足够让它输给任何一步正常的活）。☠ **不是 `-inf`** —— 执行层还有"地上的料"那条运行时
  兜底，真没别的活时它还得能试（规则 5：闸门是用来排序的）。
- **`⊕备料`**：货源解析不出来的那几样**根本不提议**（备料是"提前多做一份"，
  连货源都没有就无从备起），并打一行**去重**的日志：
```
[备料] ⚠ 这几样的**货源解析不出来**, **不提前备**: bun(链上标着'找不到货源') —— 备了也是去抓一把错的
```

**根因还没定案**（这一刀只是止血）：`Bun` 与 `ChoppedBun` 之间在知识表里
**没有任何一条边**（`next`/`ing`/`spawn` 三条路全落空）。要定案得**游戏在线**跑：

```
PYTHONUTF8=1 py runtime\_nosrc_live.py Bun ChoppedBun
```
☠ **它叫 `_live` 不叫 `_probe`** —— 离线回归是 `runtime\_*_probe.py` 那个 glob 一把梭跑的，
叫 `_probe` 会把"没开游戏"报成"回归挂了"。

### 放置对不齐时「换边」（`NEKO_ALIGN_TRY_CELLS`，2026-09-17）

用户点名的"**锅的定位不是很好**"。实机：
`⚠ 挪了 8 次, 游戏仍说放置目标是 'workstation_cooker_01 (3)'` ⇒ `mark_branch_dead`
（划掉 25 秒）⇒ `cook` 整组失败，还会带出一串 `[分支] … 这一支先划掉 25 秒`。

根因是**两层**：
- 调用点都是 `navigate_smart(spot.x, spot.z, tight=0.8)` —— **朝台面中心走**，
  而 `_stand_cell` 的注释早写明"台面是障碍格，不能朝它走"。`navigate_smart` 只保证
  "到中心 `tight` 格以内"，**从哪一侧到达完全看寻路**；灶台有四个相邻格，
  **只有朝向锅的那一侧**游戏才认。
- 老 `_align_for_place` 落空后**只会朝中心再挪一步 + 转身** —— 台面是障碍格，
  那一步要么被挡、要么把人往中心推 ⇒ **它没有任何机制能换到另一侧**。

现在落空后**围着这台子转一圈**（`max_di=1` ⇒ 相邻格恰好 8 个，跳掉脚下那格，
最多 7 次）。判据仍然只有一条：**游戏报的 `placeh`**（精确比、连实例号）——
这里只换**起点**，一行几何都不自己算。

日志：
```
[步骤] ↻ 原地挪不出来, 换到 (6.0,7.2) 再问: 游戏说放置目标='workstation_cooker_01 (1)' ✓
[步骤] ↻ 换到 (7.2,7.2) 再问: 游戏仍说 'workstation_plate_return' ✗
```
**反面断言**：`挪了 8 次…` 后面**紧跟一串** `换到 … ✗` 且整圈走完仍不成功
⇒ 不是"边选错了"，是**别的原因**（锅不在灶上 / `placeCanHandle=false`），
去看同一时刻的 `直调那一趟: … placeCanHandle=`。

### 转身那条守卫的「信游戏」退路（`NEKO_FACE_TRUST_GAME`，2026-09-17）

`face` 转身时会**实际位移 ~0.4 格**，所以它有一条守卫：目标方向那一点被地图判成危险格
就**不转身**。这条守卫本身是对的 —— 但 `is_danger_world` 是**只看格子的 2D 判据**
（不看高度），而 KillPlane 是 3D 体积 ⇒ **重生点/台面边缘/水位图很容易被投影成"危险"**。

☠ 实测（`s_rapids_3_5`）：地图一度报 `可走0 障碍36 物理阻挡0 危险75 空洞1425`
（48×32=1536 格里 1425 格是空洞）⇒ 守卫**成片拦下转身**：
```
[朝向] 目标方向是危险格, 不转身      ← 连着刷
[步骤] ⚠ 挪了 8 次, 游戏仍说放置目标是 ''(期望 'FryingStation (1)')   ← 紧接着
```
转不了身 ⇒ `placeh` 永远解析不出来 ⇒ 整个 `cook` 失败。

现在给了它一条退路，判据**和导航那条 `_danger_trust` 同源**：

> **我脚下这一格地图也说是危险格，而游戏没在重生我** ⇒ 这张图此刻的"危险"投影对不上现实。

```
[朝向] ⚠ 地图说目标方向是危险格, 但**它说脚下这格也危险、而游戏没在重生我** —— 信游戏, 这次照转
```

☠ **安全性靠"只在脚下那格也报危险时才生效"**：正常地图上厨师站在实地上，
这条**恒不触发** ⇒ 行为一字不变；只有地图**已经在乱报**时才放开。
⚠ 与导航那条的差别：导航要**等 0.6 秒**（它下一步真的要走进去），
而这里**只读一帧、不按键、不 sleep** —— 证据在脚下，不需要等，
所以它敢放在 `face` 这种高频调用的地方。

**反面断言**：`不转身` 与 `挪了 8 次` 成对出现、而且**没有** `信游戏, 这次照转`
⇒ 脚下那格地图说安全（即地图没在乱报）⇒ 那是**真的**水，去看别处。

## 两个容易踩的注意事项

**① `python -u` 不是可选的。**
`run_watch.py` 起子进程走的是**管道**，而 Python 对管道默认 8KB 块缓冲 ⇒ 日志会**攒着分批吐**，
看不到实时次序；更糟的是收尾走 `CTRL_BREAK_EVENT`，缓冲区里没吐出来的那部分**直接丢**。
`-u`（= `PYTHONUNBUFFERED=1`）关掉它。`run_watch.py` 拼子进程命令时**固定带 `-u`**。

**② "跑起来就不用管焦点了"只在两只都用手柄时成立。**
`runInBackground` 被打开的是**游戏**，而**键盘注入走 `SendInput`，只发给当前前台窗口**。
所以 `--input keys,virtual` 那种配置下，进对局之后**仍然必须保持前台** ——
否则走键盘的那只当场不动。⇒ 开 `NEKO_WATCH_KEEP_FOCUS=1`，或者跑的时候别切出去。

## 怎么查"某个参数现在是几"

参数是在**模块 import 时**读的 ⇒ 直接问那个模块（`engine.py` 顶层那些常量）：

```bat
python -c "import sys; sys.path.insert(0,'neko'); import engine; print(engine.STEP_COOLDOWN)"
python -c "import sys; sys.path.insert(0,'neko'); import engine; print(engine.CHORE_MODE, engine.PLAN_MODE)"
```

☠ **常量名和环境变量名不一定同名**，别照着猜：

| 环境变量 | 模块里的常量 |
|---|---|
| `NEKO_STEP_COOLDOWN` | `engine.STEP_COOLDOWN` |
| `NEKO_CHORES` | `engine.CHORE_MODE`（**不是** `CHORES`） |
| `NEKO_PLAN` | `engine.PLAN_MODE`（**不是** `PLAN`） |
| `NEKO_FOCUS` | `keyboard_input.FOCUS_POLICY`（**不是** `FOCUS`） |
| `NEKO_TERRAIN_TTL` | 不是模块常量，是 `World.terrain_ttl` / `Engine.terrain_ttl` |
| `NEKO_STATE_TTL` | 同上，`World.state_ttl` |
| `NEKO_COOP` | `engine.COOP`（**不是** `COOP_MODE`） |
| `NEKO_COOP_ORDERS` | `engine.COOP_ORDERS` |
| `NEKO_COOP_CLOCK` | `engine.COOP_CLOCK` |
| `NEKO_COOP_STEPS` | `engine.COOP_STEPS` |
| `NEKO_COOP_PLATE` | `engine.COOP_PLATE` |
| `NEKO_COOP_RES` | `engine.COOP_RES` |
| `NEKO_STEP_TTL` | `engine.STEP_CLAIM_TTL`（**不是** `STEP_TTL`） |
| `NEKO_PLATE_TTL` | `engine.PLATE_IDLE_TTL`（**不是** `PLATE_TTL`） |
| `NEKO_PLATE_CLAIM_TTL` | `engine.PLATE_CLAIM_TTL` |
| `NEKO_ORDER_URGENCY` | `engine.ORDER_URGENCY_CAP`（**不是** `ORDER_URGENCY`） |
| `NEKO_ORDER_URG_FLOOR` | `engine.ORDER_URGENCY_FLOOR` |

找不到的话直接搜定义处（唯一可靠的查法）：

```bat
findstr /s /n "NEKO_PLAN " neko\*.py
```
