# 参数配置

> 这份表是**从代码里扫出来的**（`os.environ.get("NEKO_…")` 全量），不是凭印象写的。
> 每一行都能在源码里搜到定义处；表格只给"这个数是干什么的 + 默认值"。

## 三分钟版

**平时什么都不用设。** 需要改的只有三样，而且它们都该写进 `runtime/watch.local`：

| 你要干的事 | 配什么 |
|---|---|
| 两个脚本自己打 | `NEKO_WATCH_CHILD=run_team.py --input keys,virtual` |
| 一个键盘一个手柄 ⇒ **必须保持前台** | `NEKO_WATCH_KEEP_FOCUS=1` |

配好之后：`python -u run_watch.py`。

## 参数本地化：`runtime/watch.local`

每开一次终端都要 `set` 一串环境变量，忘一个就跑成另一个配置 —— 而**跑错配置的代价是一整局**。
所以参数可以从一个本机文件读（`runtime/` 是 gitignore 的，不进仓库）：

```ini
# 每行 KEY=VALUE; # 开头是注释; 值里的 = 和空格都原样保留
NEKO_WATCH_CHILD=run_team.py --input keys,virtual
NEKO_WATCH_KEEP_FOCUS=1
```

- ☠ **显式设的环境变量优先于这个文件**（走 `setdefault`）——
  临时改一格 `set NEKO_CHORES=0` 仍然管用，不用去动文件。
- ☠ **这个文件能放下面这张表的全部 52 个，不只是看护那 11 个。**
  看护起子进程时 `Popen` **不带 `env=`** ⇒ 整个环境变量原样传给子脚本
  （实测：文件里的 `NEKO_CHORES` / `NEKO_STEP_COOLDOWN` 子进程都收得到）。
  ⇒ **一个文件配完所有东西**。
- 换路径：`NEKO_WATCH_LOCAL=<别的文件>`；**关掉它**：`NEKO_WATCH_LOCAL=0`。
- 它由 `run_watch.py` 读取（`parse_local_config`，纯函数，`runtime/_watch_probe.py` 有断言）。

## 两个容易踩的注意事项

**① `python -u` 不是可选的。**
`run_watch.py` 起子进程走的是**管道**，而 Python 对管道默认 8KB 块缓冲 ⇒ 日志会**攒着分批吐**，
看不到实时次序；更糟的是收尾走 `CTRL_BREAK_EVENT`，缓冲区里没吐出来的那部分**直接丢**。
`-u`（= `PYTHONUNBUFFERED=1`）关掉它。`run_watch.py` 拼子进程命令时**固定带 `-u`**。

**② "跑起来就不用管焦点了"只在两只都用手柄时成立。**
`runInBackground` 被打开的是**游戏**，而**键盘注入走 `SendInput`，只发给当前前台窗口**。
所以 `--input keys,virtual` 那种配置下，进对局之后**仍然必须保持前台** ——
否则走键盘的那只当场不动。⇒ 开 `NEKO_WATCH_KEEP_FOCUS=1`，或者跑的时候别切出去。

## 怎么查"某个参数现在是几"

参数是在**模块 import 时**读的 ⇒ 直接问那个模块（`engine.py` 顶层那些常量）：

```bat
python -c "import sys; sys.path.insert(0,'neko'); import engine; print(engine.STEP_COOLDOWN)"
python -c "import sys; sys.path.insert(0,'neko'); import engine; print(engine.CHORE_MODE, engine.STEP_COOLDOWN)"
```

☠ **常量名和环境变量名不一定同名**，别照着猜：

| 环境变量 | 模块里的常量 |
|---|---|
| `NEKO_STEP_COOLDOWN` | `engine.STEP_COOLDOWN` |
| `NEKO_CHORES` | `engine.CHORE_MODE`（**不是** `CHORES`） |
| `NEKO_FOCUS` | `keyboard_input.FOCUS_POLICY`（**不是** `FOCUS`） |
| `NEKO_TERRAIN_TTL` | 不是模块常量，是 `World.terrain_ttl` / `Engine.terrain_ttl` |
| `NEKO_STATE_TTL` | 同上，`World.state_ttl` |

找不到的话直接搜定义处（唯一可靠的查法）：

```bat
findstr /s /n "NEKO_CHORES " neko\*.py
```

用户原话：**"锅起火的话不会灭火，地上的火已经验证过了还可以"**。

插件那张火表（`dyn.fires`）只扫 `ServerFlammable`/`ClientFlammable` —— **灶台/锅不在里面**。
而 `_rescues` 遇到烧起来的锅是 `continue`（注释写着"走灭火那条路"）
⇒ **锅烧起来没人管，一路烧到报废**。

`_fire_targets(km)` 现在从 `km.cooking` 的 `burning` 补一条（`type:"CookingBurn"`，
坐标取**锅自己的**），`extinguish` 那一整套（走过去 → 面向 → 喷 0.9s → 确认）
**原样适用，插件一行不用改**。

⚠ 两条来源是**相加不是替换**：插件读失败时**照样**去补锅那条
（原来 `return []`，插件抖一下就把锅那一路一起丢了）。

**离线**：`runtime\_fire_probe.py`（13 条，**改前是 `TypeError`**：老签名 `_fire_targets(self)`

## 队友通报"我在干嘛"（`NEKO_MATE_SYNC`，2026-09-17）

用户原话：**"厨师1的信息需要强制同步给厨师2，让脚本知道另外一个在干嘛，
包括位置，在做的事，指向的对象，手上的东西，需要是什么"**。

五项里**只有两样要新通报**：

| 项 | 来源 |
|---|---|
| 位置 / 手上的东西 / **指向的对象**（`pick`/`use`/`placeh`） | 共享的 `World.state()` 那份 `chefs[]` —— **本来就有**（新鲜度靠 `NEKO_CHEF_HZ`） |
| **在做的事** / **需要是什么** | 引擎内部 ⇒ 黑板 `OrderBoard.publish_status` |

2026-09-18 按用户点名的三个问题又扩了两格（都是"**没传就保留上一条**"，普通通报不会抹掉）：

| 字段 | 答什么 |
|---|---|
| `did` | **我做了啥** —— 刚做完的那一步（`fetch Cucumber`） |
| `op` | **我打算做啥** —— 选中并正在做的那一步（发布时机就是"选中那一刻"） |
| `left` | **我做完了吗** —— 这一单还剩几步（`0` = 这单我做完了） |

☠☠ **它是"通报"不是"占位"**：只发布、只读、**只用来错开一步**
（队友正在做**同一步** ⇒ 我顺到链上的下一步），**不加任何锁** ——
队友那条过期了、或者他其实做不成，这一步还得有人做（规则 5：宁可重复，也别让人站着）。
⇒ `_stoves` 一个字节都不动（探针有一条专门钉这个）。

"需要是什么"**两个都要**：平时**广播**"我卡在缺 X"；真卡住（连续失败上冷板凳）
再发一条**带自己的 TTL（`team.ASK_TTL` = 5s）的正式求助** ——
求助和通报是**两件事**，通报一直刷、求助只喊一次，所以 TTL 分开判。

**两端都接了**（2026-09-18 起）：

```
他在做这一步（op 就是这一步）        ⇒ 我跳过它，顺到链上的下一步
他在为这一步求助（ask 就是这一步）    ⇒ **不跳**，这一步我做（搭手）
两者都没有 / 通报过期                ⇒ 当"不知道", 照链的顺序走
```

  ☠ 方向必须是这样：求助 = "**我做不成这一步**"（`_mate_ask` 是连续失败上冷板凳之后
  喊的）⇒ 那一步还得有人做，而它本来就在链上。所以 `ask` 必须**压过** `op`：
  只看 `op` 就会在"他刚喊完"那一小段里绕开它。
  ☠ **没有复用 `pass`**（交接包原话"要复用 `pass`"，查过：那半边已全覆盖）——
  `pass` 是"**我**做不了 ⇒ 把料丢给他做"。他求助的三种现场：台面我够得着 ⇒
  自己做（就是这条）；台面我够不着 ⇒ `_pass_candidates` 条件②已提议 `pass`、
  条件④ `_mate_can` 还替他验了走得到；我够不着且没拿料 ⇒ 那边先选 `fetch` 再 `pass`。
  再造一条 `pass` 候选只会重复，还会把"我自己能做的事"丢给他。

**日志指纹**（2026-09-17 补，`_mate_trace`）：这条通道是**旁路**，不加指纹就**分不出**
"没生效"和"生效了、只是两人本来没撞车"（两种都是"什么都没发生"）。
四个 kind 各答一个问题：

| 行 | 答什么 |
|---|---|
| `[队友通报] 开 —— …` | 启动时说明开关状态（关了时 `_mate_publish` 直接 return，不单独说就分不出"关了"和"没选出来"） |
| `[队友通报] ↑ 我: …` | **我发布出去了**吗 |
| `[队友通报] ↓ 队友: …` | **我读到队友**了吗、他做的是哪一步；`(过期/被清)` 与 `(**从来没有过** —— 通道没通)` 分开说 |
| `[链] 队友在做 … —— 我顺到链上的下一步` | 那条通报**真改变了我的选择**吗（2026-09-18 起；原来的 `⤵ 让开` / `✚ 搭手` 随评分层删了） |

`↑` 有而 `↓` 一直"从来没有过" ⇒ **通道只出不进**（他没发布／不是同一块黑板／cid 对不上）；
`↑`/`↓` 都有、两边步骤不同 ⇒ **生效了，本来就没撞车**。指纹**只在内容变化时打**。

**离线**：`runtime\_matesync_probe.py`（通报通道）+ `runtime\_chainexec_probe.py` §3/§3b
（错开与搭手的**行为**）。⚠ `_matelog_probe`/`_matehelp_probe` 随评分层一起删了。**实机未验。**
