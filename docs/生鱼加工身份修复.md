# 生鱼加工身份修复

2026-09-18，气球关海鲜意面长时间无法做完。实机知识接口明确返回：Fish 的 next=UncookedFish、stages=8；ChoppedFish 的 ing=UncookedFish、next 为空。食材箱 spawn=Fish、spawnNext=UncookedFish。日志对应 fetch Fish 成功后，chop UncookedFish 被“手上是 Fish，不是 UncookedFish”拒绝，继而丢下生鱼。

原因：菜谱的 chop.target 是加工后的食材身份，执行和评分却拿生料物体名做精确比较。

依据：读取 ServerWorkableItem.HasFinished IL_0000–0015（进度达到 stages-1）；ItemKnowledge.cs:263–272 从 WorkableItem.GetNextPrefab 提取后继食材，当前桥返回了上述实际关系。无需通过名称猜测 Fish 的用途。

新增 `_held_choppable`，依据知识表 next 或食材箱 spawnNext 判断生料是否能加工成目标。接入切菜候选、菜板选择、板上材料核验、分区备料和 chop 交接；不放宽通用物品匹配，也不把 ChoppedFish 当成仍待切的生鱼。

79 项回归测试通过。覆盖 Fish→UncookedFish、Prawn→Prawn、错误材料拒绝、已加工鱼拒绝、只存在箱子知识的情况，以及切菜候选和交接入口。内存恢复旧同名匹配，新测试出现 1 个断言失败、0 个运行错误。
