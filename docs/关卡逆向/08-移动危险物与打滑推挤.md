### 1.2 ⭐ 输入闸门的三个条件（先确认这个，再谈别的）

任何按键要生效，必须同时满足（都在 `PlayerControls.CanButtonBePressed()` 里，`PlayerControls.cs:453-468`）：

1. `Application.isFocused` —— **游戏窗口必须在前台**；否则连底层逻辑按键都会把自己的按下/抬起事件"吃掉"（`LogicalButtonBase.Update` 末尾的 `ClaimPressEvent/ClaimReleaseEvent`，`LogicalButtonBase.cs:92-96`）。
2. `GetDirectlyUnderPlayerControl()` —— 该 pad 的**当前活跃厨师**必须是自己（`PlayerSwitchingManager.cs:45-59` 的 `SetDirectlyUnderPlayerControl`），且没有被 `Suppressor` 压制（`PlayerControls.cs:470-497`）。
3. 没有打开的对话框 / 没有打开的根菜单（`PlayerControls.cs:463`）。

→ 由 2 推出的**开环杀手**：`PlayerSwitchingManager.AvatarSet.ActiveAvatar` 决定"这个 pad 的按键属于哪只厨师"，而**只要有厨师死亡，重生流程会强制切换**（见 §3.8）。脚本以为在驱动 A，实际在驱动 B，且不会有任何报错。

### 1.3 ⭐ 按键事件是"轮询边沿"，不是"硬件边沿"

`LogicalButtonBase.JustPressed()` 的实现（`LogicalButtonBase.cs:15-40、79-97`）：

- `IsDown()` 为真且本次尚未被 claim → 返回 true 并立刻 claim；
- 每次 `Update(_isDown)` 里 `m_pressClaimed = m_pressClaimed && _isDown`：**只要被看到"抬起"一次，claim 状态就复位**。

推论（对脚本很重要）：

- 长按 `IsDown`-型输入（方向键）**不会被吞**：厨师被禁用/被压制期间不轮询，重新启用后第一次轮询看到 `IsDown=true && 未 claim` → 当作"刚按下"。位移类操作安全。
- **"点一下"型输入（拾取/使用/冲刺）如果在厨师被禁用期间完成按下+抬起，则彻底丢失**：重新启用后第一次轮询看到的是"抬起"，边沿已被跳过。
- 显式吞事件的调用点：`ControlSchemeData.ClearEvents()`（`PlayerControls.cs:122-136`）会在 **会话开始**（`ServerSessionInteractable.cs:38`）、**会话开始/结束**（`ClientPlayerControlsImpl_Default.cs:746、756`）、**暂停菜单显隐**（`:936`）、**换人**（`ServerPlayerControlsImpl_Default.cs:96`）时被调用。

→ 脚本规则：**动作键不要在打滑/重生/接管/换人窗口内按**；宁可晚 0.5s 补按一次。

## 2. 关键类型与字段

### 2.1 "打滑"其实是两条彼此独立的通道

#### (a) 击倒式打滑 `SlipCollider`（= splat 地面）

```
SlipCollider (MonoBehaviour)          SlipCollider.cs:3-11     m_slipFilter=-1, m_deleteOnSlip=true
   ├ ServerSlipCollider               ServerSlipCollider.cs:5-66
   └ ClientSlipCollider               ClientSlipCollider.cs:3-5  （空壳，纯同步占位）
PlayerSlipBehaviour                   PlayerSlipBehaviour.cs:5-36
   ├ ServerPlayerSlipBehaviour        ServerPlayerSlipBehaviour.cs:5-75
   └ ClientPlayerSlipBehaviour        ClientPlayerSlipBehaviour.cs:5-119  （只做特效）
PlayerSlipMessage                     PlayerSlipMessage.cs:6-11   Slip / Stand / Finished
```

- 触发方式**不是** `ITriggerReceiver`，而是**物理碰撞/触发器**：`ServerSlipCollider.OnCollisionEnter/OnTriggerEnter` → `ObjectAdded`（`ServerSlipCollider.cs:47-65、30-37`）。层掩码 `m_slipFilter` 默认 `-1`（全层）。
- `ClientPlayerSlipBehaviour` 确实实现了 `ITriggerReceiver`（`ClientPlayerSlipBehaviour.cs:5`），但**只用于播撞击粒子**：收到 `m_impactTrigger`（默认 `"FallImpact"`）时生成 impact 特效（`:112-118`）。**它不影响位移，也不影响输入**。
- 触发源脚本 = 任何挂 `SlipCollider` 的物体；`m_deleteOnSlip` 为真时**踩一次就销毁自己**（`ServerSlipCollider.cs:24-27`），并且 `m_slipped` 列表保证"同一次重叠期间不重复触发第二名（同一物体）厨师"（`:32-36`）。
  → **非幂等**：谁先踩谁挨摔，后到的厨师不会摔。双人脚本若依赖"A 先趟过油污给 B 清路"，这正好可用；若依赖"两人都摔"，则结果依时序而变。

#### (b) 摩擦式打滑 `PlayerPhysicsSurface.Slippiness/Slidiness`

- 组件：`PlayerPhysicsSurface`（`PlayerPhysicsSurface.cs:3-6`）持有 `PlayerPhysicsSurfaceProperties`（`PlayerPhysicsSurfaceProperties.cs:5-18`：`SpeedMultiplier=1`、`Slippiness`、`Slidiness`、`UseOverrideGravityNormal`、`OverrideGravityNormal`、`GravityMultiplier=1`）。
- 挂钩点：厨师的 `GroundCast` 地面变化 → `PlayerControls.OnGroundChanged` 记录当前面（`PlayerControls.cs:801-804`），对外暴露 `PlayerControls.PhysicsSurface`（`:410`）。
- 生效点：**每一物理子步**的速度混合公式 `ProgressVelocityWrtFriction`（`ClientPlayerControlsImpl_Default.cs:852-870`）：

```
num3   = Remap(Slippiness, 0, 1, 1, deltaTime)          // :861
vector2= SpeedMultiplier * 目标速度 * num3
       + 上一帧速度        * (1 - num3)                  // :863
Slidiness 额外把横向速度按地面法线倾斜权重注入            // :867-869
```

  - `Slippiness = 0` → 目标是 `1×`、上一帧是 `0×` → 按键立刻生效（正常地面）。
  - `Slippiness = 1` → `num3 ≈ deltaTime ≈ 0.0166` → **目标速度只占 1.7%，上帧速度占 98.3%** → 按键几乎改变不了运动方向/速度，厨师靠动量滑行。**这就是"冰面"。**
- ⚠️ `UseOverrideGravityNormal / OverrideGravityNormal / GravityMultiplier` 三个字段在本 build 中**没有任何读取点**（全仓 grep 仅命中声明处 `PlayerPhysicsSurfaceProperties.cs:13-17`）→ 这两个功能**未启用/死字段**（重力方向翻转的重力关在本地版本里读不到实现 → **未验证**）。

### 2.2 风与喷雾器（恒定推力）


- 进入/离开由物理事件维护：`WindVolume.OnTriggerEnter/Stay/OnCollisionEnter/Stay` → `IWindReceiver.AddWindSource`（`WindVolume.cs:23-67`），`Awake/OnEnable` 还会做一次 `Physics.OverlapBox` 补录（`:69-79、118-126`）。

  - 水枪 `GetVelocity() = transform.forward * m_waterGunSpray.m_knockbackForce`（`ServerWaterGunSpray.cs:92-95`）；该值是 prefab 值（**未验证**）。
  - 命中判定 `IsInSpray`：以**施术厨师**为原点，前方锥形，半径 `sprayDistance + 0.6`，角度 `m_sprayAngleInDegrees`（`ServerSprayingUtensil.cs:117-139`）；施术者自己在原点（`num2 = 0` 不满足 `> 0`）→ **不会推到自己**（`:126-127`）。
- 物品侧的风：`ServerAttachmentWindReceiver.FixedUpdate` 对**未附着**的物品 `Movement(velocity)`（`ServerAttachmentWindReceiver.cs:21-31`）；**离开风区时会把风源速度"加"进物品速度**（一次性冲量，`:38-45`）。台面上则是 `TabletopWindReceiver` 直接把 `AttachStation` 的 collider 关掉并甩出物品（`TabletopWindReceiver.cs:15-28`）。

### 2.3 冲量式外力（"被撞飞"）

全部集中在 `ClientPlayerControlsImpl_Default`：

| 来源 | 触发函数 | 公式 | 时长 | 备注 |
|---|---|---|---|---|
| 被**投掷中**的物品撞到 | `OnThrowableCollision` (`:760-794`) | `ThrownImpactData.Multiplier(2) × 接触法线XZ × 相对速度大小` | `ThrownImpactData.Time = 0.2` | 被自己扔的东西撞**不生效**（`GetThrower() == m_iThrower` 直接 return，`:763`）；只有 `IsFlying()` 的物体算（`:763`） |
| 撞到**火**（`FireHazard`） | `OnFireHazardCollision` (`:835-850`) | `HazardImpactData.Multiplier(2) × 水平法线 × 相对速度大小` | `HazardImpactData.Time = 0.2` | 由 `OnCollisionEnter` 里 `obj.RequestInterface<FireHazard>() != null` 触发（`:514-519`） |
| 冲刺对撞（厨师↔厨师） | `OnDashCollision` (`:529-563`) | `DashImpactData.Multiplier(2) × 方向 × 相对速度大小` | `DashImpactData.Time = 0.2` | 双方都在冲刺时→**双方都吃冲量**，且朝向被强制改写（`:543-557`）；单方冲刺→只撞飞对方（`:560`） |
| 风 / 喷雾 | `ApplyWindForce` (`:902-906`) | 风矢量作为速度，**位移式**施加 | 持续（风箱 0.2s） | 不走冲量，不衰减 |

统一入口与衰减：

```csharp
ApplyImpact(Vector2 _xzImpactVelocity, float _impactTime)   // ClientPlayerControlsImpl_Default.cs:895-900
    m_impactVelocity = FromXZ(_xzImpactVelocity, 0);
    m_impactStartTime = m_impactTimer = _impactTime;
```

物理子步里的合成（`ClientPlayerControlsImpl_Default.cs:419-432`）：

```csharp
if (m_dashTimer   > 0) vector2 = Lerp(vec2,  冲刺速度, SinusoidalSCurve(dashTimer/DashTime));   // :419-424
if (m_impactTimer > 0) vector2 = Lerp(vec2, m_impactVelocity, SinusoidalSCurve(m_impactTimer/m_impactStartTime)); // :426-430
vector2 = Vector3.ClampMagnitude(vector2, movement.MaxSpeed);   // :432   ← 上限 12
```

→ **冲量是"限时接管速度"，不是"推一把"**：`0.2s` 内速度被 S 曲线地从按键速度插值到冲量速度再插值回来。位移 ≈ 冲量速度 × 0.2s，被 `MaxSpeed=12` 截断 → 单次撞飞**最多约 2.4 世界单位 = 2 格**（1 格 = 1.2）。这是足以毁掉"走到台前按使用"的误差量。

另外 `DoKnockback` 里有一条保护：冲刺中（`m_dashTimer > 0`）**免疫投掷物击退**（`ClientPlayerControlsImpl_Default.cs:796-814`，`flag = m_dashTimer <= 0f`），但**不免疫火**（`Fire` 分支不检查 `flag`，`:806-808` 只是取 `impactTime`）。

### 2.4 位移通道（带动 / 漂移 / 归一化）

- `RigidbodyMotion`（厨师的运动封装，`RigidbodyMotion.cs:4-77`）：
  - `SetVelocity` = 直接写刚体速度（`:23-26`）；
  - `Movement(v, delta)` = `MovePosition(pos + v*delta)` —— **位置增量**（`:38-46`）；风与传送带都走这条；
  - `Accelerate(f)` = `AddForce(ForceMode.Acceleration)`（重力用，`:33-36`）。
- `SurfaceMovable`（厨师身上的"我在什么移动面上"）：`Update()` 每帧询问 `IMovingSurface.CalculateVelocityAtPoint`（`SurfaceMovable.cs:42-52`），地面变化时切换 surface（`:54-70`）。
- `Travelator : IMovingSurface`：`GetSurfaceVelocity() = m_speed × GetTravelDirection()`（`Travelator.cs:134-137`），**`m_speed` 默认 1**（`:11-12`）。⚠️ 枚举命名反直觉：`XZDirection.Rightwards => -base.transform.right`（`:167-175`）。传送带之间会做"交界处提前接管"的判定（`:69-110`）。
- `PlayerControls.MovementScale`：全局位移倍率（`PlayerControls.cs:390`、`:499-502`），会在 `vector2 = movementScale * vector * RunSpeed` 里相乘（`ClientPlayerControlsImpl_Default.cs:413-414`）→ **置 0 = 按什么键都不动**（喷雾器用，见 §2.5）。
- 移动平台：`PilotMovement`（`PilotMovement.cs:4-61`，`MoveSpeed=4`、`SnapHalfLife=0.1`）+ `ServerPilotMovement`（`ServerPilotMovement.cs:54-143`）——**只有被 Terminal 驾驶时才动**（见 §3.6）。
- 网络归一化：`ClientChefSynchroniser`（`ClientChefSynchroniser.cs`）对**本机操控**的厨师做修正：静止且无输入时直接把 `localPosition` 写成服务器坐标（`:378-397`），移动中按误差施加 `CorrectionForce=4`（`:59、528-531`），误差过大（`sqrMagnitude > 6.25`，即 > 2.5 单位）或纯垂直偏差 → `Teleport`（`:491-518、540-545`）。

### 2.5 会话接管（控制权被转移的三件套）

- 基类 `ServerSessionInteractable.SessionBase`：进入会话时 `PlayerControls.enabled = false`、`Rigidbody.isKinematic = true`、`ControlScheme.ClearEvents()`（`ServerSessionInteractable.cs:28-40`）；退出时全部恢复（`:42-58`）。
- **退出条件**（客户端同构，`ServerSessionInteractable.cs:83-103`）：按 **拾取 / 使用 / 冲刺** 任一键，或"不再由本 pad 直接控制"，或被另一名**冲刺中**的厨师撞到。
- 进入条件：`CanInteract` 要求**手上是空的**（`:153-161`）→ 拿东西时不会误触发。
- 三件套：
  1. **Terminal**（驾驶移动平台）：`ServerTerminal.UserSession` 把**厨师的 ControlScheme** 交给平台的 `ServerPilotMovement`（`ServerTerminal.cs:9-22`）→ 之后方向键驾驶的是平台，厨师本体冻结。
  2. **PushableObject**（推箱子）：会话里把厨师 `SetParent` 到推物的挂点、并**关掉厨师的 `DynamicLandscapeParenting`**（`ServerPushableObject.cs:9-22`），退出时恢复并 `ForceUpdateNow()` 地面（`:24-40`）。
  3. **Cannon**（大炮）：见 §2.6。
- **喷雾器**（不是会话但同样是"控制权降级"）：只要手持风箱/水枪/灭火器并按住使用键 → `SetMovementScale(0f)`（`ClientSprayingUtensil.cs:104`），松手/卸下恢复 `1f`（`:126`、`ServerSprayingUtensil.cs:58-65`）→ **按着使用键就走不动**。

### 2.6 ⭐ 大炮与弹射物

## 3. 运行时流程（时序）

### 3.1 ⭐ 每个 Update 里的 1/60 子步（决定性：谁先谁后）

`ClientPlayerControlsImpl_Default.Update_Movement`（`ClientPlayerControlsImpl_Default.cs:393-466`）：

```
Update_Movement(dt):
  m_LeftOverTime += dt;  dt = 1/60                       // :395-396  固定步长！
  vector = 按键方向(XZ, normalized)                       // :403（GetControlAxis，:402 用 normalized）
  while (m_LeftOverTime >= 1/60):                         // :405-407
      Update_Rotation(...)                                // :408
      Update_MovementSuppression(...)                     // :409
      ApplyGravityForce()                                 // :410  ← Accelerate(AddForce)
      ApplyWindForce(dt)                                  // :411  ← MovePosition(+ 风 * dt)
      vector2 = movementScale * vector * RunSpeed         // :413-414（被抑制时置零 :415-418）
      [冲刺 S 曲线混合]                                    // :419-424
      [冲量 S 曲线混合]                                    // :426-431
      vector2 = ClampMagnitude(vector2, MaxSpeed=12)      // :432
      finalV  = ProgressVelocityWrtFriction(上帧游戏速度, 刚体物理速度, vector2, 地面摩擦)  // :433, :852-870
      Motion.SetVelocity(finalV)                          // :434
      ApplyGroundMovement(dt)   // 传送带：MovePosition(+ 带速 * dt)  // :436 → :926-930
      [冲刺键 JustPressed 判定 + 冲刺碰撞收集]                // :437-459
```

要点：

1. **风的位移在按键速度之前施加，传送带的位移在最后叠加** → 三者在同一子步内矢量叠加，且都**不受 `MaxSpeed` 限制**（风/带速走 `MovePosition`，绕过了 `:432` 的 clamp）。
2. 子步固定 `1/60`（`:396`），与渲染帧率解耦（`m_LeftOverTime` 累加），所以"按键时长 → 位移"在正常帧率下是稳定的，**但一旦遇到风/带/冲量，稳定关系就断了**。
3. 冲量期间（`m_impactTimer > 0`）**按键仍然被读取**，只是被 S 曲线降权 → 表现为"挣扎着往回走"，而不是"完全失控"。

## 5. 对自动化的含义（重点）

### 5.1 三类判定

**A 类：按键开环"根本不可能可靠工作" → 脚本应直接拒玩该关**
1. **`MeteorManager` 陨石关**：时刻与格子双随机（`MeteorManager.cs:32、40-42`）。任何预先编排的走位都会被打死。
2. **弹射物关（`m_randomTargetOrder = true`）**：落点顺序随机（`ProjectileSpawner.cs:51`），若弹射物 prefab 带 `ServerFireHazardSpawner` 还会在随机格生成火（`ServerProjectileSpawner.cs:106-110`）。
3. **车辆（`RespawnType.Car`）横穿的关**：接触即死（`ServerRespawnCollider.cs:28-49`），车辆运动完全由动画驱动，C# 无任何可读参数（§2.8 → 未验证）。**加上死亡会触发 0.5s 强制换人 + 3s 淡出 + 5s 倒计时**（§3.8），一次死亡就把开环时序彻底打崩。
4. **会"关闭通路格"的随机动画机关**：`ServerTriggerAnimatorSetVariable(m_randomValue) / TriggerAfterRandomTime`（`ServerTriggerAnimatorSetVariable.cs:22-44`、`TriggerAfterRandomTime.cs:24-43`）。若该机关决定"某格能不能走"，脚本无法预判。
5. **要求"穿越持续性致命面（Hit 型 RespawnCollider）"**的关：踩上去不是被推走而是直接死（`ServerRespawnCollider.cs:41-49`），没有容错空间。

**B 类：可玩，但必须加"补偿 / 重试 / 复位"（脚本补丁）**
1. **打滑区（SlipCollider / splat）**：禁用 `0.38 + m_downTime + 0.42` 秒（§3.2）。**位置不会漂，只是时间轴被推迟**。补丁：① 整段动作后追加 ≥ 1.5s 余量或按"行走命令复用"；② **只用长按方向键**，不要用 tap（tap 在禁用窗口内会被吞，见 §1.3）；③ 若两人有交接动作（A 递给 B），交接点必须加"等待按键/等待可见状态"而不是死等固定延时 —— 因为一次打滑就错 1 秒以上。④ 注意 `m_deleteOnSlip=true`：**同一块 splat 只坑第一个人**（`ServerSlipCollider.cs:24-27`），次序改变会改变谁被耽误。
2. **滑面（`PlayerPhysicsSurface.Slippiness > 0`）**：按键不再线性控制（§2.1b）。补丁：在该面上把步长切碎（短按短停）、并预留刹车距离；若 `Slippiness` 接近 1，应该**判定为不可精确停位**，改为"目标格中心 ±0.5 格"的粗定位，或用撞击式对齐（撞墙停下）。
3. **传送带（`Travelator`）**：恒定叠加 `m_speed`（默认 1）。补丁：按方向加减按键时长（顺行缩短、逆行延长）；注意命名反直觉（`Rightwards = -transform.right`，`Travelator.cs:167-175`）；相邻传送带交界有"提前接管"（`:69-110`）→ 提前刹车。
4. **风区（`WindVolume`）**：恒定速度漂移，方向固定（`transform.right`）、开关由机关控制（`enabled`）。补丁：标定 `m_windSpeed`（每关一次即可，风速不变），在风区内的按键时长按 `(目标位移)/(RunSpeed ± wind)` 换算；**逆风长距离位移可能根本走不到**（风速 > RunSpeed 时不可能前进）→ 需要检测"是否在风区"。
5. **被同伴撞/推**：非冲刺碰撞没有 C# 逻辑，纯物理（量级未验证）；冲刺对撞则双方各吃 `2 × 相对速度 × 0.2s`（§2.3）。补丁：**两人路线绝不交叉、并保持 ≥1.5 格间距**；脚本禁止按冲刺键（除非刻意用于 A→B 的击退对齐）。
6. **被自己的投掷物打中**：只有"别人扔的飞行物"才击退（自己扔的免疫，`ClientPlayerControlsImpl_Default.cs:763`）→ **双人脚本里 A 的投掷轨迹绝不能穿过 B**；固定投掷路线的关卡要么改路线，要么让 B 在 A 投掷窗口内站到掩体侧。
7. **客户端模式（非主机）**：松手瞬间会被服务器坐标吸附（`ClientChefSynchroniser.cs:393`）。补丁：把它当"免费复位"——**每个动作段之间停 0.2~0.5s 不按键**，让位置对齐，再执行下一段，可显著抑制误差累积。
8. **移动平台关**：只要脚本不驾驶 Terminal，平台静止（`ServerPilotMovement.cs:62`），网格占用稳定 → **可玩**。但要处理：① 开局吸附移动（§3.6）；② 若关卡强制需要驾驶平台（把平台开到某处才能通行），则**"驾驶期间按键驱动的是平台"**（§2.5）——脚本必须显式进入/退出该状态并分别编排键序。

**C 类：只需注意（一次性的小影响）**
- 手持喷雾器并按住使用键 → 完全不能移动（`ClientSprayingUtensil.cs:104`）。若配方需要灭火：站在目标前喷完**松手再走**，键序里不要"边喷边走"。
- 风箱/水枪会把锥形范围内的**同伴**（和物品）推开（`ServerBellowsSpray.cs:91-94`）→ 不要在同伴前方喷（`IsInSpray` 不会推到自己，`ServerSprayingUtensil.cs:126-127`）。
- 误按使用键站在 Terminal / 推物 / 大炮前（且空手）→ 被接管（§3.9）。补丁：**空手经过这些机关时不要按使用键**；脚本对"使用键"的按下都要带前置条件（朝向 + 目标已确认）。
- 台阶 `Steppable` 会直接把 position 写到台阶面上（`ClientPlayerControlsImpl_Default.cs:881-893`，限高 0.65）→ 只在有台阶的地方影响。
- 过场动画期间所有厨师被 `Suppress` 并 `SetActive(false)`（`ClientCutsceneController.cs:165-173`）→ 等待其结束。
- 暂停菜单 / 对话框打开时**所有按键失效**（`PlayerControls.cs:453-468`）→ 脚本必须保证窗口焦点（`Application.isFocused`）。

### 5.2 ⭐ 可执行规避清单（按严重度排序）

> 用法建议：把 A 类做成**关卡级黑名单**（进入关卡前判定，命中即拒绝自动游玩并提示人工）；B 类做成**执行期的修饰器**（在计划上叠加时间/位移补偿）；C 类做成**键序约束**（写进动作库）。

**A 级（拒绝自动游玩）**
- A1 关卡含 `MeteorManager`（陨石随机落点）—— 判定方式：场景对象名/组件扫描（BepInEx 侧 `FindObjectOfType<MeteorManager>()`）。
- A2 关卡含 `ServerProjectileSpawner` 且 `m_randomTargetOrder == true` —— 拒绝；若必须尝试，至少只走"远离 `m_targetPositions` 集合"的路线。
- A3 关卡存在 `RespawnType.Car` —— 接触即死且车辆时序不可读，拒绝。
- A4 关卡含 `TriggerAfterRandomTime` / `ServerTriggerAnimatorSetVariable(m_randomValue)` 且该机关影响通行格 —— 拒绝（无法预判"什么时候能过"）。
- A5 关卡要求"必须踩上会消失/会移动的致命面（Hit 型）" —— 拒绝。

**B 级（加补偿后允许）**
- B1 存在 `SlipCollider` / `SplatHazard`：动作时间轴整段 ×1.2 或每段后 +1.5s；只用长按；交接动作改为"等待可见状态"。
- B2 存在 `PlayerPhysicsSurface.Slippiness > 0`（滑面）：目标格容差放宽到 ±0.5 格；禁止在该面上做精确停位。
- B3 存在 `Travelator`：按方向与 `m_speed` 补偿按键时长；交界处提前 0.2 格刹车。
- B4 存在 `WindVolume` 且 `enabled`：先标定风速；逆风位移做可行性检查（`wind ≥ RunSpeed` 时该方向的位移目标直接判不可达）。
- B5 双人路线交叉 / 同格经过：禁止；间距 ≥ 1.5 格；禁止冲刺键。
- B6 存在投掷动作：检查投掷直线是否穿过同伴，穿过则改路线。
- B7 客户端（非主机）模式下：每段动作后插入 0.2~0.5s 的"松键对齐窗"。
- B8 存在 Terminal 驾驶：把"驾驶段"和"步行段"分开编排，进出都用同一个键（使用/冲刺）并各留 0.3s 稳定期。

**C 级（写进键序约束即可）**
- C1 不要在手持喷雾器时按住使用键行走。
- C2 不要在同伴前方喷风箱/水枪。
- C3 空手经过 Terminal / 推物 / 大炮前不要按使用键。
- C4 打滑/重生/接管期间不要补按"点按型"动作键（会被吞）。
- C5 保持游戏窗口前台；不要在有对话框/菜单时按键。
- C6 死亡后**必须重新确认"当前按键属于哪只厨师"**（强制换人），把该 pad 切回目标厨师再继续。

### 5.3 ⭐ 脚本侧建议新增的 3 个检测/补偿原语

1. **位置校验点（checkpoint）**：每个动作段结束后停键并读一次位置/所在格；与预期格不一致 → 触发"重对齐"（走到最近格心）或降级重试。这同时覆盖了 P5（物理推挤累计误差）、P3（网络修正）、B3/B4（带/风漂移）。
2. **"静止等待"原语**：`wait_idle(t)` = 松所有键 t 秒。它同时解决：客户端吸附对齐、冲量衰减（0.2s）、打滑结束判定（≥0.8s 起更安全）。
3. **状态黑名单扫描（进入关卡时一次）**：扫描场景里是否存在 `MeteorManager` / `SlipCollider` / `WindVolume` / `RespawnCollider(Car)` / `Travelator` / `ServerPilotMovement` / `ServerProjectileSpawner` —— 直接生成该关的"补偿参数表"或拒绝。
