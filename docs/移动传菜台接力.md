# 移动传菜台接力（2026-09-18）

s_balloon_2_2 前三局送餐为 0。日志确认厨师已拿着完整料理，但送餐台在另一侧且实时地形不连通。窗口截图显示底部有横向移动的餐桌区域，上面四个台面可用于传盘。

## 实现

直接送餐失败后，记录各 counter 的位置。观察到同一台面移动超过 0.6 世界单位后，才把它视为移动传菜台。仅尝试空台面，依旧通过实时寻路、游戏放置目标对齐及实际交互完成放置。

放置前重新确认台面为空、手持盘子未变；放置后确认手空、目标台面上仍是当前配方的完整料理。成功后释放盘子的原归属，让送餐侧现有 serve_any 逻辑接手。发送方在盘子还在移动台面时等待，不立即拿回来，也不把放下盘子算成订单完成。

机制依据：ServerAttachStation.CanHandlePlacement IL_0032–0054 通过 CalculatePlacementType 判断能否放置。没有添加扔盘子、跨空洞直走或改分数的操作。
