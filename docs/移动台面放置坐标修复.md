# 移动台面放置坐标修复

2026-09-18，气球关仍卡关。会话 `20260918-110700/cooking.log` 在 1789703234–1789703235 记录 P2 持续围绕旧菜板站位尝试，游戏报告放置目标为其他箱子。代码核对发现 `_align_for_place` 只通过 `_fresh_station_name` 刷新名字，后续方向和微步始终使用调用时传入的旧 Station 坐标；备用换边路径也围绕旧坐标生成。

依据：本机 Assembly-CSharp.dll 的 `InteractWithItemHelper.IsColliderInArc` IL_0000–0055，以当前 Collider 表面点计算距离及方向。因此移动后的目标不能继续使用旧站位快照。

改动：放置对齐每个采样周期按 station id 刷新位置和名字；换边开始时更新目标，导航失败不继续假装到位；途中目标移动超过现有接近逻辑的阈值时停止使用旧站位列表，交还上层重新规划。仍由游戏 placeh 精确匹配判定能否放置。

验证：78 项测试通过，新增用例覆盖连续两帧目标方向变化以及换边途中目标移动。内存恢复旧坐标逻辑后，新用例出现 1 个断言失败、0 个运行错误。通过 supervisor resume 重载厨师，不重启游戏、不改存档。

本次修复针对已确认的坐标过期问题，尚不能宣称气球关通关。
