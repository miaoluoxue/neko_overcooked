## 修改

- 选择摆盘位前排除不符合该配方的盘子，缓存和绑定优先分支也必须遵守；不同配方盘子不能让备料步骤“假完成”。
- 洗盘使用共享任务占位，异常或返回时释放。
- 已确认开始洗涤后，在仍面对同一水槽的情况下连续观察到洗涤交互结束，可以完成任务；不再单靠干燥台净增量。
- 手持不同食材时，不允许额外备料和回溯取料抢走执行机会。
- Python 游戏桥增加线程与跨进程锁，覆盖发请求到收到回复；缓存 state/orders/ping 无需占用主线程任务槽，保持并行读取。当前保护要求调用者使用本仓库 BridgeClient，任意外部裸 TCP 客户端仍可能绕过锁；对外 LLM 接口使用数据库快照，不直接访问 TCP。
- 击退只等待最初 0.6 秒，持续受击时允许正常移动输入，避免火场附近无限停住。
- 同一场景、同一回合中，出菜口实例变化表明厨房已整体更换：重建厨师执行进程、地图、任务缓存和角色映射。短暂没有出菜口时保持原标识，避免重复重启；普通台面移动和食物变化不触发。
- 有真实承载台面或持有者的食物模型，不再被识别成地上散落原料；装盘黄瓜不能被当作未加工黄瓜去捡。
- 已完成菜品的交付决策权重调整到与手持菜品交付相同，减少菜已做好却继续取料直到订单过期。没有修改游戏计分、计时或配方规则。
